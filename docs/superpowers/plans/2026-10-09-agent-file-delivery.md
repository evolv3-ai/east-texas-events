# Event Schedule agent file delivery implementation plan

Goal: publish the four generated public files reliably after successful synchronization, without changing ingestion or synchronization behavior.

Architecture: validate the generated bundle against the validated seed and saved ID map; transfer an immutable release over pinned-host SSH; verify checksums and atomically switch a relative symlink under the existing static mount. Caddy serves only the intended paths. Verify public responses against the exact generated bytes and roll back the pointer on failure.

Scope: workflow, new validation and delivery modules, Caddy routing, deployment tests and documentation. Keep existing generators and sync logic unchanged. Production rollout follows PR review and server provisioning.

## Task 1: Validate generated and published bundles

1. Add failing regression tests for empty, stale, future-dated, missing, inconsistent, unsynchronized and mismatched bundles, and legitimate cancellation behavior.
2. Implement a TypeScript validator using existing Zod parsing, publication policy and static generators. Require exact expected file contents and mapped active events; cancelled events remain in JSON without a public event page.
3. Add a read-only CLI supporting local validation and public HTTP verification, requiring correct content types, CORS, status and exact bytes. A 48-hour maximum age catches missed daily publication; allow an empty bundle only with explicit operator acknowledgement.
4. Run the new tests and existing suite.

## Task 2: Deliver and expose the bundle

1. Add failing real-filesystem tests for atomic activation, incomplete uploads, checksum failures, retries, superseded releases and rollback.
2. Add SSH delivery with strict known-host verification and a non-root deployment user. Upload to a staging directory, lock activation, verify all four checksums, switch current atomically and retain previous release for rollback. Do not replace the mounted parent directory.
3. Gate publication on main, non-dry-run success and successful ID-map persistence; check deployment configuration before sync. Preserve map saving after sync failure.
4. Route all four files through current; remove committed placeholders and ignore runtime releases. Add PR CI and deployment documentation, including one-time migration and public verification.
5. Run regression tests, build, shell checks and real Caddy HTTP tests when available.

## Review focus

- Failed/partial sync and dry runs cannot publish.
- A bad upload never replaces the previous good release.
- Rebase or seed/map drift must stop publication.
- Old workflow runs cannot overwrite a newer release; retries and rollback must be safe.
- Cancellation and past/archived events must retain existing feed semantics.
