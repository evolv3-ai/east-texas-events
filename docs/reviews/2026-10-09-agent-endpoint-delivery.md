Implemented the missing publication path on a feature branch. No production files, secrets,
events or server configuration were changed during this work. Production rollout requires the
reviewed Caddy configuration and a dedicated SSH publisher configured as documented in the
deployment README.

## Changes

- Validate all four generated files against the Zod-validated seed, ID map and successful live
  sync report. Catch missing events, incorrect counts or URLs, missing mappings, empty feeds,
  stale timestamps, future timestamps and inconsistent generated files.
- Publish only after successful synchronization and ID-map persistence, on main and outside
  dry-run mode. Preserve ID-map recovery after interrupted or failed synchronization.
- Upload over pinned-host SSH to a release directory, verify all four checksums, and atomically
  switch a relative symlink beneath the existing Caddy directory mount.
- Reject older workflow runs. Retry only through a new Actions attempt after failed verification.
  Verify public status, MIME type, CORS and exact generated bytes; attempt compare-and-swap
  rollback on failure, disconnect or cancellation.
- Explicitly route the four intended public paths in Caddy. Remove committed placeholder feeds.
  Missing files return 404, and unrelated application documentation does not leak into these routes.
- Add PR regression CI, a read-only production smoke-check mode, and operator instructions for
  provisioning, migration, verification, empty-feed acknowledgement, rollback and retention.

The existing event ingestion, synchronization algorithm, source data, ID map and static generators
are unchanged. Cancellation and archive behavior remain intact.

The execution environment blocks the Unix socket used by the tsx CLI. For the local full build,
its dependency-only launcher was temporarily replaced with `node --import tsx`, then restored.
No repository code was changed for this environment workaround. GitHub CI runs the standard
commands using the repository's Node 22 configuration.

## Rollout limits

The SSH transport was tested with controlled subprocess failures; activation and rollback were
also tested against real local filesystems. An authenticated transfer to the production host was
not performed. Configure the dedicated SSH account, pinned host key, deployment secrets and
static-root variable before merging or dispatching the new workflow.

Install and validate the reviewed Caddy configuration before the first publication. During the
initial migration, these four paths intentionally return 404 until a validated release exists.
The calendar and API remain separate. A lost connection may prevent automatic rollback; a failed
job requires checking the current pointer and public files. An external read-only monitor is
recommended to detect a scheduled workflow that never starts.
